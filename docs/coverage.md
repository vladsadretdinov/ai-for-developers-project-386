# Проверка покрытия сценариев

Сопоставление требований из описания приложения с операциями TypeSpec-спецификации.
Спека компилируется без ошибок (`npm run build`) и генерирует OpenAPI 3
в `tsp-output/openapi.yaml`.

## Сценарии владельца календаря

| Требование из ТЗ                                              | Операция                                  | Статусы            |
|---------------------------------------------------------------|-------------------------------------------|--------------------|
| Профиль владельца используется по умолчанию                   | `GET /admin/owner`                        | 200                |
| Создавать типы событий (id, название, описание, длительность) | `POST /admin/event-types`                 | 201, 422           |
| Просматривать список типов событий                            | `GET /admin/event-types`                  | 200                |
| Получать/редактировать/удалять тип события                    | `GET/PUT/DELETE /admin/event-types/{id}`  | 200, 204, 404, 422 |
| Страница предстоящих встреч — все типы в одном списке          | `GET /admin/bookings`                     | 200                |
| Просмотр и отмена конкретного бронирования                    | `GET/DELETE /admin/bookings/{bookingId}`  | 200, 404           |

## Сценарии гостя

| Требование из ТЗ                                       | Операция                                          | Статусы            |
|--------------------------------------------------------|---------------------------------------------------|--------------------|
| Страница видов брони (название, описание, длительность)| `GET /public/event-types`                         | 200                |
| Открыть детали вида брони                              | `GET /public/event-types/{id}`                    | 200, 404           |
| Открыть календарь свободных слотов на 14 дней          | `GET /public/event-types/{id}/slots`              | 200, 404           |
| Создать бронирование на выбранный слот                 | `POST /public/bookings`                           | 201, 404, 409, 422 |

## Покрытие ключевых правил

| Правило                                                       | Где зафиксировано                                            |
|---------------------------------------------------------------|--------------------------------------------------------------|
| На одно время — только одно бронирование (любой тип)          | `SlotTakenError` → `409` в `POST /public/bookings`           |
| Окно записи 14 дней от текущей даты                           | `SlotList.windowStart/windowEnd` + `409` при записи вне окна |
| Запись только на свободный слот                               | `GET .../slots` отдаёт только свободные; `409` при гонке     |
| Конец встречи считается сервером по длительности типа         | `Booking.end` и `Slot.end` помечены read-only                |
| Анонимность гостя (без аккаунта)                              | в `BookingCreate` только `guestName`/`guestEmail`/`notes`    |

## Вывод

Все пункты описания приложения (роли, сущности, окно 14 дней, правило занятости,
публичный сценарий гостя и админские действия владельца) покрыты операциями
спецификации. Контракт проверяется компиляцией:

```bash
npm install
npm run build   # tsp compile spec -> tsp-output/openapi.yaml
```
