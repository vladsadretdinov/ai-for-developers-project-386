# Контрибьютинг

## Формат коммитов — Conventional Commits

В проекте обязательны коммиты по спецификации
[Conventional Commits](https://www.conventionalcommits.org/). На их основе
[release-please](https://github.com/googleapis/release-please) автоматически
формирует `CHANGELOG.md` и предлагает новую версию по правилам
[SemVer](https://semver.org/).

### Структура

```
<type>[optional scope]: <описание>

[optional body]

[optional footer(s)]
```

### Основные типы

| Тип        | Когда использовать                          | Влияние на версию |
|------------|---------------------------------------------|-------------------|
| `feat`     | новая функциональность                      | minor (0.x.0)     |
| `fix`      | исправление бага                            | patch (0.0.x)     |
| `perf`     | оптимизация производительности              | patch             |
| `refactor` | рефакторинг без изменения поведения         | —                 |
| `test`     | добавление/изменение тестов                 | —                 |
| `docs`     | документация                                | —                 |
| `build`    | сборка, зависимости                         | —                 |
| `ci`       | конфигурация CI                             | —                 |
| `chore`    | прочее (служебное)                          | —                 |

### Ломающие изменения

`BREAKING CHANGE:` в футере или `!` после типа (`feat!:`) поднимают **major**
версию.

### Примеры

```
feat(guest): добавить выбор слота в календаре
fix(backend): возвращать 409 при пересечении интервалов
test(e2e): покрыть основной сценарий бронирования
docs: описать пользовательские сценарии для e2e
ci: запускать Playwright на pull request
```

### Scope (необязательно)

Рекомендуемые области: `frontend`, `backend`, `e2e`, `spec`, `guest`, `admin`, `ci`.

## Коммиты, которые делает агент

ИИ-агент (OpenCode и др.) обязан соблюдать тот же формат. Правила для агента
зафиксированы в [`AGENTS.md`](./AGENTS.md).
